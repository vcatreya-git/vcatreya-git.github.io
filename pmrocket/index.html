The problem

The navigation gap

Every major PM prep platform teaches frameworks and interview techniques. None solves the upstream problem.

🧭

No role matching

Platforms assume you already know which PM role to target. None maps your background to the right archetype — so candidates prepare generically for roles that don't fit them.

📊

No market-grounded readiness signal

Existing readiness scores use invented internal rubrics with no connection to what employers actually screen for. "You're at 62" means nothing without market grounding.

🗂️

No evidence practice

Employers require portfolio evidence — PRDs with success metrics, A/B test documentation, domain analyses. Platforms teach frameworks to talk about evidence without building any.

How it works

A five-stage intelligence pipeline

Each stage feeds the next. No stage is skippable.

1

Intake

15 questions capturing background, skills, domain, geography, and PM experience signals

2

Weighted Match

4 PM archetypes scored across all 15 signals with admin-configurable weights

3

3-Layer Curriculum

Universal AI literacy + archetype-specific + domain × geography artefact roadmap

4

Evidence Log

Self-attestation with progressive tiers: Learning → Practised → Mastered, auto-computed

5

RAG Gap Analysis

Gap % vs real JD requirements. Ready-to-apply gate at ≤30% gap, no critical skill gaps

Technical depth

Under the hood

Production-grade design decisions — not a toy demo.

Weighted matching

15-signal archetype scoring

score(A) = Σ[w(q,A) × raw(q,A,answer)] ──────────────────────────── Σ w(q,A)

15 intake signals weighted per archetype. Admin-configurable via question_weights table — no code deploy to tune behaviour. Tie-breaking: Q12 (technical skills) absolute contribution decides.

RAG gap analysis

JD-grounded readiness signal

pgvector HNSW (m=16, ef=64) → top-25 JDs by profile similarity → LLM: gap_pct + top 3 skill gaps

On-demand, not auto-triggered. Corpus-gated: gap analysis hidden if fewer than 15 JDs exist for the user's archetype × domain × geography slice.

LLM abstraction

Provider-agnostic inference

ACTIVE_LLM_PROVIDER=groq|anthropic|google

Vercel AI SDK provider factory. Groq (Llama 3.3 70B, free tier) is the default. Swap provider with a single env var — zero code changes. Designed for Vercel → AWS Fargate portability from day one.

ETL pipeline

Market-current curriculum ops

JD paste → Claude extract → admin approve/reject → pgvector embed

Vocabulary-constrained extraction prevents skill drift. Corpus minimum gates unlock gap analysis per slice. Admin reviews every skill before it touches the live curriculum.
