Architecture V3.0

PMRocket — Vercel + Neon + Clerk + Vercel AI SDK

V3.0 — Active Updated 2026-07-18 Replaces Supabase-era V2.1
What changed from V2.1: Supabase replaced by Neon (database) + Clerk (auth) + Next.js API routes (backend logic). LLM calls abstracted via Vercel AI SDK — provider-swappable via env var. Docker from day one for Vercel → AWS portability. All business logic, data model, and API contracts are unchanged.

Stack Decision

PMRocket runs on free tiers until there is real traction. The personal phase stack is chosen for zero ongoing cost and maximum portability — the same Docker image runs on Vercel today and AWS ECS Fargate when scale demands it.

System Components

Next.js Frontend + API Routes

Role: Full-stack layer. Server-rendered React app for all user-facing screens. API routes handle all backend logic — replacing Supabase Edge Functions (Deno) and PostgREST.

Key constraint: Standard Node.js API routes only — no Vercel Edge Runtime primitives. This keeps the codebase portable to any Node.js host (ECS Fargate, Fly.io, self-hosted).

Auth integration: @clerk/nextjs — auth() in server components and API routes. JWT validation on every protected route.

DB access: @neondatabase/serverless — HTTP-based driver, works in serverless without connection pool configuration.

Clerk Auth

Role: User registration, login (email + Google OAuth), session tokens, role management.

Admin role: Set via Clerk Dashboard → User → publicMetadata: { role: "admin" }. Checked in every admin API route.

User provisioning: Clerk fires user.created webhook on signup. Handler at /api/webhooks/clerk creates users, user_profiles, and subscriptions rows — replacing Supabase's handle_new_user trigger.

User ID format: Clerk userIds (e.g. user_2abc...) are stored as TEXT PKs in all user tables. No UUID.

Neon PostgreSQL + pgvector

Role: All application data + vector embeddings for JD similarity search.

Why Neon over Supabase: No pausing on the free tier (Supabase pauses after 7 days inactivity — breaks demo flows). pgvector is a first-class built-in extension. No lock-in to Supabase-specific APIs. Schema is pure PostgreSQL — identical on Neon, RDS, or any Postgres host.

pgvector config: HNSW index m=16, ef_construction=64 on jd_embeddings.embedding. Cosine similarity, K=25 retrieval for gap analysis. Sub-100ms ANN at V2a scale — no Pinecone required.

LLM — Vercel AI SDK

Provider-agnostic interface for all text generation and structured output. ACTIVE_LLM_PROVIDER env var selects provider at runtime.

Default: Groq (Llama 3.3 70B) — free tier, strong structured output, fast inference.

Fallback: Anthropic claude-sonnet-4-6 — paid, highest quality for gap analysis narratives.

Embeddings — Vercel AI SDK

Provider-agnostic interface for JD and profile embedding. ACTIVE_EMBED_PROVIDER env var.

Default: OpenAI text-embedding-3-small (1536 dims, $0.02/1M tokens).

Constraint: All providers must output 1536-dim vectors. Changing dimensions requires a migration + full re-embed of all JDs.

Stripe Integration

Role: Subscription creation, paywall enforcement, cancellation. Test mode for Alpha — live charges activated after traction.

Flow: Stripe Checkout redirect from frontend → webhook at /api/stripe/webhook → update subscriptions table.

Paywall guard: SubscriptionGuard component checks subscriptions.status via /api/subscriptions. API routes also check subscription before serving paid content.

LLM Abstraction

All LLM and embedding calls go through a provider factory in src/lib/llm.ts. Switching provider requires changing a single env var — no code changes, no deploy of new logic.

// src/lib/llm.ts — provider factory

import { createGroq }               from '@ai-sdk/groq'
import { createAnthropic }          from '@ai-sdk/anthropic'
import { createGoogleGenerativeAI } from '@ai-sdk/google'
import { createOpenAI }             from '@ai-sdk/openai'

export function getLLMModel() {
  const provider = process.env.ACTIVE_LLM_PROVIDER ?? 'groq'
  switch (provider) {
    case 'anthropic': return createAnthropic()('claude-sonnet-4-6')
    case 'google':    return createGoogleGenerativeAI()('gemini-2.0-flash')
    case 'groq':
    default:          return createGroq()('llama-3.3-70b-versatile')
  }
}

export function getEmbedModel() {
  const provider = process.env.ACTIVE_EMBED_PROVIDER ?? 'openai'
  switch (provider) {
    case 'voyage':
      return createOpenAI({ baseURL: 'https://api.voyageai.com/v1' })
               .textEmbeddingModel('voyage-3-lite')
    case 'openai':
    default:
      return createOpenAI().textEmbeddingModel('text-embedding-3-small')
  }
}

POST /api/gap-analysis — key contract

// Request
{ user_id: string }  // must match authenticated userId

// Processing
1. Verify auth.userId === user_id (ownership check)
2. Fetch active archetype_match
3. Check corpus minimum (≥15 JDs for this archetype × domain × geography slice)
4. Build profile text from intake_responses + evidence_log
5. AI SDK embed() → 1536-dim profile vector
6. pgvector cosine similarity K=25, pre-filtered by domain/geography/archetype
7. Compute gap_pct (deterministic, app-side):
   gap_pct = (1 − artefacts_with_evidence / total_roadmap_artefacts) × 100
8. AI SDK generateText() → top_gaps + qualitative summary
9. Write to gap_analyses table

// Response (200)
{ gap_analysis: { id, gap_pct, jds_used, top_gaps, summary, ready_to_apply } }

// Errors
401 UNAUTHORIZED · 403 FORBIDDEN · 422 NO_MATCH
422 THIN_CORPUS · 422 NO_SUBSCRIPTION · 429 RATE_LIMIT_EXCEEDED
502 LLM_ERROR · 500 INTERNAL_ERROR

// Rate limit: 3 requests / 24 hours / user

POST /api/extract-skills — key contract

// Request (admin only)
{ jd_queue_id: string, domain: string, geography: string }

// Processing
1. Verify admin role from Clerk publicMetadata
2. Read jd_ingestion_queue row (status must be 'pending')
3. Set status = 'processing'
4. AI SDK generateObject() with Zod schema:
   z.object({ skills: z.array(z.object({
     skill_name: z.string(),
     skill_category: z.enum(['technical','product','business','domain'])
   })) })
   Prompt includes existing skill_frequency vocabulary list — prevents fragmentation
5. Return preview only — NOT written to DB until admin approves

// Response (200)
{ jd_id, extracted: [{ skill_name, skill_category }] }

// Approve via: POST /api/confirm-extraction
// Reject: status = 'rejected', row stays in queue for review

Migration runner

No Supabase CLI dependency. Tracks applied migrations in a migrations table. Each migration runs in a transaction — failure rolls back cleanly.

// scripts/migrate.ts
import { neon }       from '@neondatabase/serverless'
import { readFileSync, readdirSync } from 'fs'
import { join }       from 'path'

const sql = neon(process.env.DATABASE_URL!)

async function migrate() {
  await sql`CREATE TABLE IF NOT EXISTS migrations (
    id          SERIAL PRIMARY KEY,
    filename    TEXT   NOT NULL UNIQUE,
    applied_at  TIMESTAMPTZ DEFAULT NOW()
  )`

  const applied    = await sql`SELECT filename FROM migrations`
  const appliedSet = new Set(applied.map(r => r.filename))
  const files      = readdirSync('./supabase/migrations').sort()

  for (const file of files) {
    if (appliedSet.has(file)) continue
    const sql_text = readFileSync(join('./supabase/migrations', file), 'utf-8')
    await sql.transaction(async tx => {
      await tx(sql_text)
      await tx`INSERT INTO migrations (filename) VALUES (${file})`
    })
    console.log(`Applied: ${file}`)
  }
}

migrate().catch(console.error)

// Run: npx tsx scripts/migrate.ts

ENV NODE_ENV=production

CMD ["node", "server.js"]

Vercel → AWS migration path

Build Docker image: docker build -t pmrocket .
Push to AWS ECR: docker push [account].dkr.ecr.[region].amazonaws.com/pmrocket
Provision RDS PostgreSQL + pgvector. Restore schema: pg_dump from Neon → RDS restore.
Update DATABASE_URL in ECS task definition environment. All other env vars unchanged.
Configure ECS Fargate task definition. CloudFront distribution in front of ALB. Done.

Clerk and Vercel AI SDK run unchanged — both are cloud-agnostic. No provider-specific code in the application layer.

Key Design Decisions

Decisions made during the 2026-07-18 infrastructure rethink. Full log in 08-Decision-Log.md.

Why Neon over Supabase?
Supabase free tier pauses after 7 days inactivity — breaks portfolio demos. Neon free tier never pauses. pgvector is built-in on Neon. Pure PostgreSQL schema means zero lock-in.
Why Vercel AI SDK over direct API calls?
Provider abstraction — swap Groq → Anthropic → Gemini via one env var. No code changes, no redeploy. Critical for cost management: Groq free tier covers Alpha volume; upgrade to Anthropic for quality only when needed.
Why Docker from day one?
Vercel → AWS ECS Fargate migration is infrastructure config only, not a rewrite. Writing the Dockerfile now means the migration path is proven before it's needed.
Why application-level auth, not RLS?
RLS on Neon requires Clerk JWT template configuration — extra setup that's not needed until the product phase. API route enforcement (WHERE user_id = $userId) is simpler, explicit, and testable. RLS definitions are present in migrations and can be activated at the product phase.
Why pgvector HNSW over Pinecone?
No additional service dependency. HNSW (m=16, ef=64) gives sub-100ms ANN at V2a scale (thousands of JDs, not millions). Avoids the $70/mo Pinecone Starter cost at zero users. Migrate to managed vector DB only if pgvector becomes a bottleneck at scale.
Why Next.js API routes, not Edge Functions?
Edge Runtime primitives lock code to the Vercel/Cloudflare ecosystem. Standard Node.js API routes run anywhere. Full npm ecosystem available. Same code deploys to Vercel and ECS Fargate.
Why Groq as default LLM?
Free tier with generous rate limits covers Alpha volume entirely. Llama 3.3 70B has strong structured output capability — sufficient for ETL skill extraction and gap analysis narrative. Anthropic is available as a quality fallback for high-stakes outputs.
