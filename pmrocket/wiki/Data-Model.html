Data Model

The PMRocket schema is driven by three core concepts: user profiles, artefact curricula (three-layer), and evidence logs. This page documents the key tables and relationships.

Core Entity Diagram

users (TEXT id from Clerk)
  ├── user_profiles (user_id TEXT FK)
  ├── archetype_matches (user_id TEXT FK)
  ├── intake_responses (user_id TEXT FK)
  ├── evidence_log (user_id TEXT FK → artefacts.id)
  ├── readiness_scores (user_id TEXT FK)
  ├── gap_analyses (user_id TEXT FK → jd_embeddings)
  └── subscriptions (user_id TEXT FK)

archetypes
  └── question_weights (archetype_id FK, question_id FK)

artefacts (layer, category, geography)
  └── skill_frequency (artefact_id FK, archetype_id FK, geography_type)

jd_embeddings (vector column, HNSW indexed)
  └── extracted_skills (jd_id FK, skill_name)

Users and Profiles

users

Primary user table; ID is Clerk's user ID format (user_2abc...).

Column Type Notes
id TEXT PRIMARY KEY Clerk user ID, never UUID
email TEXT UNIQUE Provisioned via Clerk webhook
first_name TEXT Used in greeting: "Hi, {first_name} 👋"
last_name TEXT —
created_at TIMESTAMPTZ —
updated_at TIMESTAMPTZ —

user_profiles

Extended user data; one row per user.

Column Type Notes
user_id TEXT PRIMARY KEY FK → users.id —
avatar_url TEXT User-uploaded or initials placeholder
primary_archetype_id UUID FK → archetypes.id Matched during intake
primary_archetype_confidence NUMERIC 0.0–100.0 %, e.g., 92.5
secondary_archetype_id UUID FK → archetypes.id Runner-up match
intake_completed_at TIMESTAMPTZ NULL until first intake finish
intake_started_at TIMESTAMPTZ Tracks session begin time
geography TEXT 'North America' | 'India' | ... (from Q5)
job_title_goal TEXT User's target role; from Q11
created_at TIMESTAMPTZ —
updated_at TIMESTAMPTZ —

Intake and Matching

intake_responses

Responses to all 15 assessment questions; one row per question per user.

Column Type Notes
id SERIAL PRIMARY KEY —
user_id TEXT FK → users.id —
question_id INTEGER 1–15
response TEXT or JSONB Single value or array depending on Q type
created_at TIMESTAMPTZ —
updated_at TIMESTAMPTZ —

Q1–Q11 and Q15: response is TEXT (single choice or checklist as JSON array)
Q12–Q14: response is NUMERIC (1–5 rating)

archetype_matches

Match result from POST /api/compute-match; one row per user per computation.

Column Type Notes
id UUID PRIMARY KEY —
user_id TEXT FK → users.id —
primary_archetype_id UUID FK → archetypes.id Highest-scoring archetype
primary_score NUMERIC Weighted sum, 0–100
secondary_archetype_id UUID FK → archetypes.id Runner-up
secondary_score NUMERIC —
signal_breakdown JSONB { "background": 18, "experience": 22, "skills": 25, "domain": 15, "goals": 12 }
computed_at TIMESTAMPTZ —

question_weights

Weights for each question × archetype pair; configurable at runtime by admin.

Column Type Notes
id SERIAL PRIMARY KEY —
question_id INTEGER 1–15
archetype_id UUID FK → archetypes.id —
weight NUMERIC Typically 1–10
score_map JSONB Maps response choice → raw_score (0.0–1.0)
created_at TIMESTAMPTZ —
updated_at TIMESTAMPTZ —

Example score_map for Q1 (background):

{
  "Software Engineer": { "Technical PM": 1.0, "Consumer PM": 0.3, "Data PM": 0.9 },
  "Product Manager": { "Technical PM": 0.7, "Consumer PM": 0.95, "Data PM": 0.6 },
  "Finance/Analyst": { "Technical PM": 0.2, "Consumer PM": 0.5, "Data PM": 0.8 }
}

Artefacts and Curriculum (Three-Layer)

archetypes

Eight PM archetypes; static seed data.

Column Type Notes
id UUID PRIMARY KEY —
name TEXT 'Technical PM' | 'Consumer PM' | ...
description TEXT 2–3 sentence description of the archetype
icon TEXT emoji or image path
created_at TIMESTAMPTZ —

artefacts

The core curriculum; every artefact is tagged with layer, category, and geography.

Column Type Notes
id UUID PRIMARY KEY —
title TEXT e.g., "Write 10 SQL Queries"
description TEXT 50 chars; e.g., "Practice SQL SELECT, JOIN, GROUP BY on a toy dataset"
layer TEXT 'Universal' | 'Archetype' | 'Domain'
archetype_id UUID FK → archetypes.id NULL if layer = 'Universal'
geography TEXT 'North America' | 'India' | NULL (all geographies)
category TEXT 'Technical' | 'Business' | 'Portfolio' | 'Domain' | 'Product'
max_points INTEGER Points awarded at Mastered tier: 8 (Technical), 5 (Portfolio), etc.
key_topics TEXT[] Array of 15 topics; auto-split into 3 tiers of 5 each
search_keywords TEXT[] 5 keywords; clickable in evidence modal for "Search to learn"
skill_area TEXT e.g., 'SQL', 'Python', 'Go-to-market', 'Case studies'
skill TEXT Specific skill; e.g., 'Database Querying'
tier_unlock_celebration BOOLEAN Show animation on tier unlock (default true)
created_at TIMESTAMPTZ —
updated_at TIMESTAMPTZ —

key_topics structure (example for "Write 10 SQL Queries"):

[
  "Learn SELECT with WHERE clause",
  "Practice INNER and LEFT JOINs",
  "Understand GROUP BY and aggregates",
  "Write subqueries",
  "Study indexes and query optimization",

  "Query a real production schema",
  "Debug slow queries with EXPLAIN",
  "Optimize queries for performance",
  "Handle NULL values correctly",
  "Write reusable views",

  "Debug complex edge cases",
  "Teach SQL querying to a peer",
  "Optimize queries under load",
  "Contribute to data modeling discussions",
  "Mentor junior analyst on SQL"
]

Tiers:
- Learning: topics 0–4 (SELECT, JOINs, GROUP BY, subqueries, indexing)
- Practised: topics 5–9 (production schema, EXPLAIN, optimization, NULL, views)
- Mastered: topics 10–14 (edge cases, teaching, load optimization, data modeling, mentoring)

Evidence and Readiness

evidence_log

Every artefact logged by a user creates one row per tier progression.

Column Type Notes
id UUID PRIMARY KEY —
user_id TEXT FK → users.id —
artefact_id UUID FK → artefacts.id —
tier TEXT 'Learning' | 'Practised' | 'Mastered'
description TEXT Optional; 200 char max user description
link TEXT Optional; auto-prefixed with https://
topic_progress JSONB { "0": true, "1": true, "3": false, ... } — topic checkboxes
unlocked_at TIMESTAMPTZ When this tier was unlocked
created_at TIMESTAMPTZ —

Multiple evidence rows for one artefact means the user progressed through tiers (first Learning, then Practised, then Mastered).

readiness_scores

Computed score snapshot; one row per user, UPSERTed on every evidence log.

Column Type Notes
user_id TEXT PRIMARY KEY FK → users.id —
total_score NUMERIC Sum of all artefact_maxpoints × tier_multiplier
category_breakdown JSONB { "Technical": 6, "Business": 2, "Portfolio": 5, "Domain": 3, "Product": 4 }
computed_at TIMESTAMPTZ When the score was last updated

The score is deterministic: same evidence set always yields the same total.

Gap Analysis and JDs

jd_embeddings

Embedded job descriptions for RAG retrieval.

Column Type Notes
id UUID PRIMARY KEY —
jd_text TEXT Full original job description
source_url TEXT URL where JD was sourced (admin metadata)
company_name TEXT e.g., "Stripe" (metadata for context)
archetype_id UUID FK → archetypes.id Categorized by archetype
geography TEXT 'North America' | 'India'
domain TEXT 'Fintech' | 'B2B SaaS' | ...
embedding vector (1536 dims) OpenAI text-embedding-3-small output
created_at TIMESTAMPTZ —

HNSW index: CREATE INDEX idx_jd_embeddings_vector ON jd_embeddings USING hnsw (embedding vector_cosine_ops) WITH (m=16, ef_construction=64)

extracted_skills

Skills extracted from a JD by the LLM; used to update skill_frequency.

Column Type Notes
id SERIAL PRIMARY KEY —
jd_id UUID FK → jd_embeddings.id —
skill_name TEXT Must match vocabulary in skill_frequency
frequency INTEGER 1
created_at TIMESTAMPTZ —

gap_analyses

Gap analysis results; one row per user per analysis request.

Column Type Notes
id UUID PRIMARY KEY —
user_id TEXT FK → users.id —
gap_pct NUMERIC (1 - evidenced_artefacts / total) × 100
top_gaps JSONB Top 3 skill gaps with recommended artefacts
narrative TEXT LLM-generated qualitative analysis
jd_references JSONB Array of retrieved JD IDs (K=25 nearest)
computed_at TIMESTAMPTZ —

Admin and Taxonomy

skill_frequency

Aggregated skill occurrence across JDs for a given slice (archetype × domain × geography).

Column Type Notes
id SERIAL PRIMARY KEY —
skill_name TEXT e.g., "SQL", "GTM Strategy", "User interviews"
archetype_id UUID FK → archetypes.id —
domain TEXT 'Fintech' | 'B2B SaaS' | ...
geography TEXT —
frequency INTEGER Count of JDs containing this skill
trending BOOLEAN Frequency increased >10% in past month (admin dashboard)
in_curriculum BOOLEAN Skill already in artefacts for this slice
recommended_artefacts UUID[] Artefacts that teach this skill (populated by admin)
created_at TIMESTAMPTZ —
updated_at TIMESTAMPTZ —

jd_ingestion_queue

Admin queue for reviewing extracted skills before approval.

Column Type Notes
id UUID PRIMARY KEY —
jd_text TEXT Original JD pasted by admin
extracted_skills JSONB [{ "term": "SQL", "confidence": 0.95, "status": "pending" }]
admin_review JSONB Admin's accept/reject/edit decisions
status TEXT 'pending' | 'approved' | 'rejected'
created_at TIMESTAMPTZ —
completed_at TIMESTAMPTZ NULL until approval/rejection

subscriptions

User subscription status for paywall enforcement.

Column Type Notes
user_id TEXT PRIMARY KEY FK → users.id —
stripe_customer_id TEXT Stripe customer ID
stripe_subscription_id TEXT Stripe subscription ID
status TEXT 'active' | 'past_due' | 'canceled'
current_period_end TIMESTAMPTZ When subscription renews (or ends if canceled)
created_at TIMESTAMPTZ —
updated_at TIMESTAMPTZ —

Views

dashboard_summary_v2

Composite view joining multiple tables for efficient dashboard load.

SELECT
  u.id,
  u.email,
  u.first_name,
  up.primary_archetype_id,
  up.primary_archetype_confidence,
  (SELECT COUNT(*) FROM evidence_log WHERE user_id = u.id) AS evidence_count,
  rs.total_score,
  rs.category_breakdown,
  s.status AS subscription_status
FROM users u
JOIN user_profiles up ON u.id = up.user_id
LEFT JOIN readiness_scores rs ON u.id = rs.user_id
LEFT JOIN subscriptions s ON u.id = s.user_id

Single query loads all data for the Dashboard page — avoids N+1 queries.
