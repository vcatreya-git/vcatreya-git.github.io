API Reference

All routes use standard Next.js App Router route handlers (src/app/api/). Every protected route calls auth() from @clerk/nextjs/server, checks userId, and includes WHERE user_id = $userId on all user-scoped database queries. No query can return another user's data, even with a valid session token.

Full Contract: POST /api/gap-analysis

Auth: Clerk session required. userId from the session must match user_id in the request body.

Request body:

{
  "user_id": "user_2abc..."
}

Processing:

  1. Verify auth().userId === user_id (ownership check)
  2. Fetch active archetype_match for the user
  3. Check corpus minimum — requires ≥ 15 JDs for the user's archetype × domain × geography slice; returns 422 THIN_CORPUS if not met
  4. Build profile text from intake_responses + evidence_log
  5. Embed profile via Vercel AI SDK embed() using getEmbedModel()
  6. pgvector cosine similarity search, K=25, pre-filtered by domain / geography / archetype
  7. Compute gap_pct (deterministic, application-side):

gap_pct = (1 − artefacts_with_evidence / total_roadmap_artefacts) × 100

  1. Call getLLMModel() via generateText() — qualitative top gaps and recommendations
  2. Write result to gap_analyses table

Rate limit: 3 requests per 24 hours per user.

Response (200):

{
  "gap_analysis": {
    "id": "uuid",
    "gap_pct": 42.5,
    "jds_used": 23,
    "top_gaps": [
      {
        "skill": "System design",
        "gap_reason": "Required in 18/23 JDs; no evidence logged",
        "recommended_artefact": "System design case study"
      }
    ],
    "summary": "Your profile is strong in product sense but lacks technical depth...",
    "ready_to_apply": false
  }
}

Error codes: 401 UNAUTHORIZED · 403 FORBIDDEN · 422 NO_MATCH · 422 THIN_CORPUS · 422 NO_SUBSCRIPTION · 429 RATE_LIMIT_EXCEEDED · 502 LLM_ERROR · 500 INTERNAL_ERROR

Full Contract: POST /api/extract-skills

Auth: Clerk session required. publicMetadata.role must be "admin".

Request body:

{
  "jd_queue_id": "uuid",
  "jd_text": "We are looking for a Technical PM with...",
  "archetype_id": "uuid",
  "domain": "b2b_saas",
  "geography": "north_america"
}

Processing:

  1. Verify admin role from Clerk publicMetadata
  2. Fetch jd_ingestion_queue row; status must be pending
  3. Set status = processing
  4. Call getLLMModel() via generateObject() with structured skill extraction schema. Prompt includes the existing skill_frequency.skill_name vocabulary list to constrain output to known taxonomy terms
  5. Return extracted skills preview — nothing written to the curriculum yet
  6. On error: set status = failed, write error_message

Response (200):

{
  "jd_id": "uuid",
  "extracted": [
    { "skill_name": "System design", "skill_category": "Technical", "confidence": 0.92 },
    { "skill_name": "Stakeholder management", "skill_category": "Business", "confidence": 0.85 }
  ]
}

Error codes: 403 FORBIDDEN · 404 NOT_FOUND · 422 ALREADY_PROCESSED · 502 LLM_ERROR · 500 INTERNAL_ERROR

Auth Pattern

Every protected route follows this pattern. The ownership check (userId !== user_id) ensures users can only access their own data, even with a valid session token.

import { auth } from '@clerk/nextjs/server'

export async function POST(request: Request) {
  const { userId } = await auth()
  if (!userId) return Response.json({ error: 'Unauthorized' }, { status: 401 })

  const { user_id } = await request.json()
  if (userId !== user_id) {
    return Response.json({ error: 'Forbidden' }, { status: 403 })
  }

  // business logic ...
}

Admin routes additionally check publicMetadata.role:

import { auth, currentUser } from '@clerk/nextjs/server'

export async function POST(request: Request) {
  const { userId } = await auth()
  if (!userId) return Response.json({ error: 'Unauthorized' }, { status: 401 })

  const user = await currentUser()
  if (user?.publicMetadata?.role !== 'admin') {
    return Response.json({ error: 'Forbidden' }, { status: 403 })
  }

  // admin logic ...
}

Admin routes return 403 (not 404) to authenticated non-admin users. The 404 approach is used only at the routing layer for unauthenticated access, where revealing the existence of an admin route is an unnecessary information leak.
