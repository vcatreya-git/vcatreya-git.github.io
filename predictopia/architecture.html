Architecture

Free-tier, portable stack for multi-sport private pools. One event spine for match outcomes and specials. Settlement tracking only — no payments.

Independently reviewed

Drafted with Claude, then reviewed by a second model (Grok) before any backend code was written — not a rubber stamp. Five required changes came back, all fixed the same day.

!
Privilege-escalation gap in a leave policyA member's own "leave the group" RLS check only validated user_id, not role — a crafted request could have self-promoted to admin. Fixed with a status-pinning check plus a trigger that blocks any self-service role change.
✓
Admin-inheritance gapA group admin without their own explicit pool-membership row would have been locked out of managing pools they should administer by default — the helper function didn't carry the inheritance rule its own policy already had.
✓
A referenced function that was never definedPeriod-close cited a leaderboard() function that didn't exist anywhere in the schema — would have failed at build time. Now defined as one SUM() query with a period-type branch.
✓
Sports-API rate-limit risk, resolved structurallyFlagged as unvalidated in two earlier product reviews. Architecture confirms calls scale with real-world match count, never with how many pools or groups are predicting on the same match — concrete worst case well under the free-tier cap.

Data model (short)

Group / Pool

People vs tournament instance. Opt-in pools. Group admin creates pools; members join when they care.

Catalog

Sport → competition → season → matches. Cutoffs per competition. Shared fixtures across pools.

Events

Outcomes materialised per pool×match. Specials admin-authored. Same options / predictions / scores path.

Payouts

Period close or special resolve → owed / settled. Buy-in collected is a separate flag.
