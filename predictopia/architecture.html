Architecture — Predictopia v2

Portable free-tier design for multi-sport private prediction pools: Group/Pool membership, one event spine for match outcomes and specials, RLS-backed auth, and Splitwise-style settlement tracking (no payments).

v2 · Aug 2026 Next.js · Auth.js · Supabase Postgres · Vercel Diagrams: draw.io + SVG Backend: not live yet

Five architectural invariants

1
Nothing is tournament-shapedNo table hardcodes IPL or a single sport. Competitions are catalog rows.
2
One event spineMatch outcomes and admin specials share one events model and one scoring function.
3
Points only in event_scoresLeaderboards and period filters are SUM lenses — never a second ledger.
4
Portable identityapp.current_user_id() from a session GUC — not auth.uid(). Works on any Postgres.
5
Money never overspends the potPeriod split + tie-shrink are budget-safe by construction; closed periods snapshot immutably.

Data model (summary)

Group vs Pool

Group = persistent people (join code, admit/deny). Pool = one tournament under a group (opt-in, economics, periods). Multiple concurrent pools per group from day one.

Catalog

Sport → Competition → Season → Matches. Cutoff minutes are per competition (cricket 30; football 60 or 90). Matches are shared — API cost scales with fixtures, not pool count.

Events

One row type: outcome (materialised per pool×match) or special (admin-authored, single or multi choice, exact/partial scoring for points).

Money

payouts hang off a closed period or a resolved special. Status owed / settled. Buy-in uses a separate buy_in_collected flag — never both called “Paid.”

Identity & access

  1. Browser hits a Route Handler; Auth.js resolves Google session → internal users.id.
  2. Handler opens a transaction and set_config('app.user_id', …, true) (transaction-local).
  3. RLS policies read app.current_user_id() — membership isolation and post-cutoff reveal live in the database.
  4. Jobs use a separate app_jobs role + bearer JOB_SECRET (schedule, results, reminders).
Group Admins inherit pool-admin rights on every pool under their group; pool-level admin can still exist for the pool creator. Leave/remove cannot escalate roles.

Core flows

Predict → lock → reveal

Member upserts a prediction; a DB trigger rejects edits after lock. Cutoff is stored on the match (from competition rules). After lock, other members’ picks become visible via RLS — UI surface is Board’s collapsible Reveal section (not a separate tab).

Score

app.score_event() is the single scorer for outcomes (provider or admin override) and specials (manual resolve). Partial credit applies to multi-pick points only; special prizes require exact match.

Settlement

Admin closes a period on Money → standings snapshot + split/tie rules → payouts. Profile /me/money rolls up across pools with multi-currency lines. App never moves money.
