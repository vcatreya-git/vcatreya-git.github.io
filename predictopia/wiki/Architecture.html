Stack Decision

Reuses the proven Supabase + Next.js pattern from PMRocket. Zero monthly cost at family scale. 9-day deadline means zero room for stack exploration.

RLS Strategy

RLS is enabled on all 15 tables (10 core + feature_requests, feature_votes, top4_predictions, competitions, season_winner_predictions). The design uses a hybrid approach:

  • RLS provides a broad security floor — most tables allow authenticated read access. RLS prevents unauthenticated access and enforces write restrictions.
  • API routes enforce business rules — prediction visibility before/after cutoff, pool membership checks for data filtering, result fetch triggers, scoring cascades. These are complex to express in RLS and easier to debug in application code.

Migration 007 — RLS Nuclear Fix

The original RLS policies caused infinite recursion on pool_members: a SELECT policy queried pool_members itself to verify membership. Migration 007 drops ALL policies on ALL 15 tables and recreates them with zero recursion.

Three core principles:
1. No table's policy ever queries the same table — eliminates recursion by design.
2. pool_members policies never query pool_members — use auth.uid() = user_id for self-access, pools.created_by for creator access.
3. pools policies never query pool_members — any authenticated user can read pools (needed for join flow preview).

Key RLS policies (post-007):

Table Policy Logic
users Read: any authenticated auth.uid() IS NOT NULL
pools Read: any authenticated auth.uid() IS NOT NULL (join preview needs this)
pool_members Read own + creator sees all auth.uid() = user_id OR pool_id IN (SELECT id FROM pools WHERE created_by = auth.uid())
matches Read all auth.uid() IS NOT NULL
match_results Read all auth.uid() IS NOT NULL
predictions Read: any authenticated auth.uid() IS NOT NULL (cutoff visibility in API)
leaderboard_cache Read: any authenticated auth.uid() IS NOT NULL
prizes Read: any authenticated auth.uid() IS NOT NULL
pool_budget Read: creator only pool_id IN (SELECT id FROM pools WHERE created_by = auth.uid())
achievements Read: any authenticated auth.uid() IS NOT NULL
competitions Read: any authenticated auth.uid() IS NOT NULL

Auth Flow

  1. User taps "Sign in with Google" on the auth screen
  2. Supabase Auth handles OAuth redirect and JWT issuance
  3. If new user: frontend routes to onboarding (display name auto-populated from Google profile, avatar auto-populated, pick favourite IPL team)
  4. Profile row created in users table linked to auth.users.id
  5. If user arrived via a join link: redirect intent preserved through auth flow, resolved after profile creation
  6. Phone OTP deferred to V1.1 (may require paid Twilio)

Cron Jobs

Daily Schedule Refresh

  • When: 00:30 IST (19:00 UTC previous day)
  • What: Calls CricketData.org v1/series_info for IPL 2026. Upserts into matches table.
  • Implementation: Vercel Cron calling GET /api/cron/refresh-schedule
  • Failure: Non-critical. Schedule is pre-seeded. Cron catches new matches and time changes.

Cutoff Enforcement

Not a cron job. Enforced at query time: now() >= match.cutoff_at. No background process needed.

Leaderboard Refresh

Not a cron job in V1. Updated synchronously when a match result is scored. At family scale (15 users, 1 pool), scoring takes milliseconds. Revisit at 100+ pools.

Key Architectural Flows

Result Fetch + Score Cascade

  1. User opens a completed match card (or taps refresh)
  2. API checks match_results for cached result
  3. If no cache: calls CricketData.org, parses winner
  4. INSERT INTO match_results ... ON CONFLICT (match_id) DO NOTHING — first write wins
  5. Score all predictions for this match across all pools: 2 (correct), 0 (wrong), 1 (abandoned)
  6. Recompute leaderboard_cache for affected pools (weekly, monthly, overall)
  7. Check achievement criteria (streak, perfect week, team loyalist)
  8. Two simultaneous users: upsert race handled by DB constraint. Second write is a no-op.

Team Colour Theming (V1)

User selects favourite team at onboarding. A static JSON map provides { primary, secondary, text } per team. V1 applies primary as --team-color CSS variable to root layout — used for nav bar background, button accents, active tab indicator. Full 10-palette override across all components is V1.1.
