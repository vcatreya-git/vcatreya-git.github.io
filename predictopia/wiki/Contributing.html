Local Dev Setup

Prerequisites

  • Node.js 18+
  • npm or pnpm
  • A Supabase account (free tier)
  • A CricketData.org API key (free)

Getting started

# Clone the repo
git clone https://github.com/vcatreya-git/predictopia.git
cd predictopia

# Install dependencies
npm install

# Set up environment variables
cp .env.example .env.local
# Fill in:
#   NEXT_PUBLIC_SUPABASE_URL=
#   NEXT_PUBLIC_SUPABASE_ANON_KEY=
#   SUPABASE_SERVICE_ROLE_KEY=
#   CRICKETDATA_API_KEY=
#   CRON_SECRET=

# Run the development server
npm run dev

Database setup

Apply migrations in order:

# Using Supabase CLI (recommended)
supabase db push

# Or manually run SQL files
# 001_create_tables.sql — 10 tables with constraints and indexes
# 002_rls_policies.sql — Row Level Security on all tables

Testing the sports API

# Manually trigger schedule refresh
curl http://localhost:3000/api/cron/refresh-schedule

Coding Standards

TypeScript

  • Strict mode enabled. No any types in committed code.
  • Prefer interfaces over type aliases for object shapes.
  • Use const assertions for enums and static maps (like team colours).

Components

  • One component per file. File name matches component name.
  • Handle all four states: loading, empty, error, success.
  • 48px minimum tap targets on all interactive elements (accessibility requirement).
  • No copyrighted assets. Team abbreviations in team colours only.

API Routes

  • All routes verify auth via supabase.auth.getUser() unless explicitly public.
  • Validate at system boundaries (request body, query params). Trust internal code.
  • Time-dependent logic (cutoff enforcement, prediction visibility) lives in API routes, not RLS.
  • Use database upserts with ON CONFLICT for idempotent operations.

Database

  • RLS enabled on all tables. No exceptions.
  • All timestamps stored as timestamptz (UTC).
  • Foreign keys with ON DELETE CASCADE where appropriate.
  • Indexes on frequently queried columns (pool_id, user_id, status, scheduled_at).

Styling

  • Tailwind CSS for all styling. No custom CSS files unless necessary.
  • Team colours via CSS custom properties (--team-color).
  • Mobile-first responsive design. Test on mid-range Android phones.
  • Light theme only in V1. Dark theme is not planned.

Git

  • Conventional commit messages: feat:, fix:, refactor:, docs:, chore:
  • One feature per branch. PR into main.
  • No secrets in code. Use .env.local for local development.

Key Architecture Decisions

These decisions constrain how code should be written. Read the full Decision Log for reasoning.

  1. Hybrid access control: RLS for pool isolation, API routes for time-dependent logic. Do not put cutoff logic in RLS policies.
  2. Synchronous scoring: No background jobs in V1. Score calculation happens inline when a result is fetched. Revisit at 100+ pools.
  3. On-demand result fetch: Never poll for results. First user tap triggers the API call. Use INSERT ... ON CONFLICT DO NOTHING for the race condition.
  4. Predictions are per-pool: The UNIQUE constraint is (pool_id, user_id, match_id), not (user_id, match_id).
  5. Approve != Paid: Two separate states in pool_members. Never conflate them.
  6. Never show net loss to members: UI shows "Won X so far", never "Net -X".
