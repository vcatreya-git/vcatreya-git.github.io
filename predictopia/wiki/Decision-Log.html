Decision Log

Curated key decisions from the Predictopia brainstorming and design phases (March 2026). Grouped by category, with reasoning preserved.

Product Strategy

Decision Reasoning
Product name: Predictopia Prediction + utopia. Memorable, works for any sport, doesn't sound like betting.
Ad-supported, never charge users Friends pooling money + no house edge = not betting. Ads are cleanest monetisation.
Multi-group platform (anyone can create) Every group admin is a distribution channel. Organic growth without acquisition spend.
Multi-league architecture, IPL only at launch Schema supports any sport/league from day one. Content and API integration for IPL only in MVP.
Hard deadline: April 4, 2026 IPL started March 28. Ship MVP before too many matches pass.
Skip hypothesis and discovery phases Problem validated through 3 seasons of manual Google Sheets leagues. No market research needed for a family side project.
Primary persona: Pool Admin If admin pain is eliminated, pool survives. Admin is also the distribution channel.
North Star Metric: Prediction rate > 70% % of eligible predictions made per match. If members predict, the product works.
Alpha = family group directly No separate alpha environment. Ship to family WhatsApp group by April 4.

Authentication

Decision Reasoning
Google-only auth for V1 Family all have Google accounts. Phone OTP may require paid Twilio -- deferred to V1.1.
Google display name + avatar auto-populated Reduces onboarding friction. One less thing to type.
Pick favourite IPL team at onboarding Tints app UI, feeds Team Loyalist streak. One extra signup question.

Pools and Membership

Decision Reasoning
One permanent pool link (not per-match) Admin shares once, members pin it. No daily link generation.
Private pools only in V1 Family use case = closed groups. is_public boolean in schema for V2.
Max pool size: 100 members Prevents abuse, keeps leaderboards manageable.
Multi-admin (WhatsApp model) Familiar permissions, no learning curve. Creator can't be removed.
Creator vs Admin permission split Creator controls money + pool existence. Admins help with daily ops.
Admin removal: only Creator can Keeps power hierarchy clear. Admin steps down by leaving and rejoining.
Approve != Paid (two separate states) UPI/cash payment is async. Approve = "you're in." Paid = "I got your money."
Join flow: request + approval (paid), auto-join (free) Prevents strangers via leaked links, makes buy-in transparent.
Mid-season exit: buy-in stays in pool No refund. Predictions preserved. The buy-in is the entry fee.
Merged Admin/Settings screen One gear icon, one screen with sub-tabs. Reduces nav confusion.

Predictions and Scoring

Decision Reasoning
One-tap prediction (Team A or B, no tie) IPL has super overs -- always a winner. Simplest possible UX.
Advance predictions for next 5 matches Keeps engagement on no-match days. Changeable until cutoff.
Cutoff = fixed time before scheduled start ~30 min before. Not tied to actual toss detection. Simpler, no live toss API dependency.
Predictions visible after cutoff only Independent thinking before, banter after.
Predictions are per-pool Different pools, different strategies, different bragging rights.
Scoring: 2/0/1 (abandoned). All matches 2 pts in V1 Clean, simple. Configurable match point values deferred to V1.1.
Synchronous score calculation At family scale (15 users, 1 pool), milliseconds. Background jobs add complexity with zero benefit.
Streaks are per-pool in V1 Profile shows best active streak across pools. Cross-pool aggregate is V2.

Match Data

Decision Reasoning
CricketData.org as sports API Free tier: 100 calls/day. Fallback: Roanuz. No SportRadar needed.
Schedule: daily cron at 00:30 IST One API call/day. Catches time changes and new matches.
Results: on-demand fetch, not polled First user tap triggers API + cache. One write per match. Near-zero API usage.
On-demand fetch uses DB upsert (ON CONFLICT DO NOTHING) Handles race when two users tap simultaneously. First write wins, second is a no-op.
Admin result override for disputes Source marked as admin_override. Rare edge case only.
Match times in member's local timezone Stored UTC, displayed in browser locale. Countdown is timezone-agnostic.

Prizes and Money

Decision Reasoning
Commission slider (0-50%) Admin sets commission, system computes prize pool. No manual math.
Nx distribution formula Position N from bottom = Nx share. Intuitive, automatic.
Tie-breaking: split equally + rank inversion guard Prevents "2nd place earns more than tied-1st" scenarios.
Prize periods: weekly + monthly + season (V1) Knockout-specific pots are V1.1. Keeps V1 config simple.
Prize preview with expected member count Admin enters expected size, preview shows exact amounts. Updates live.
Commission % is admin-only Members see prize amounts, never the admin's cut.
Never show losses to members "Won X so far" only. Showing losses discourages participation.
Money stays offline MVP complexity reduction. App tracks, doesn't process payments.
Pool budget tracker (admin-only) Total collected, allocated, paid, remaining, surplus. Members never see pool economics.

Design and UX

Decision Reasoning
Light, bright, energetic -- NOT dark theme White backgrounds, vibrant team colours. Dark theme killed the IPL broadcast energy.
IPL broadcast + bet365 energy Professional, data-rich, scannable. Dark nav + white content.
No copyrighted images Team abbreviations in team colours. No logos, no player photos.
Accessibility for seniors 48px min tap targets, high contrast, clear labels.
3-tab bottom nav (My Pools / Predict / Profile) Leaderboard inside Pool Home, not standalone. Max depth 2.
Predict tab = today's to-do across all pools Grouped by pool, soonest cutoff first.
"Who hasn't predicted" visible to ALL members Social nudge. Members can tag stragglers in WhatsApp.
Share = text + link via navigator.share() in V1 Visual card (PNG) share is V1.1. Text shares are faster.

Infrastructure

Decision Reasoning
Supabase + Next.js + Vercel (all free tiers) Reuses PMRocket stack. $0/month at alpha. Zero new learning curve.
Hybrid RLS + API route access control RLS for pool isolation (static). API routes for time-dependent logic (cutoff).
Next.js API Routes (not Edge Functions) Local-dev compatible via next dev. Simpler debugging.
Notification channel as config Architecture supports WhatsApp/email/Telegram/SMS. V1: admin shares manually.
$0/month cost target at alpha All free tiers. No paid services until 1,000+ users.
