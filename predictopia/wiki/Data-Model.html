Data Model — Predictopia

Schema is driven by four product concepts: pools (multi-tenant leagues), membership + money states, per-pool predictions, and thrifty match results. Full SQL in supabase/migrations/ (001–007). Companion: Architecture, Scoring Engine.

This page is portfolio proof of product-shaped data design: every constraint encodes a product rule.

Core entity diagram

users (UUID ← auth.users)
  ├── pool_members (role, status, payment_status)
  ├── predictions (per pool × match)
  └── achievements (per pool)

pools
  ├── pool_members
  ├── predictions
  ├── prizes
  ├── pool_budget
  ├── leaderboard_cache
  ├── competitions / season & top4 predictions
  └── feature_requests (optional board)

matches (league schedule)
  ├── match_results (winner, source)
  └── predictions

Core tables (001)

users

Profile linked to Supabase auth.users.

Column Type Product note
id UUID PK → auth.users Google OAuth subject
display_name TEXT Shown on LB and share cards
avatar_url / google_avatar_url TEXT Editable vs OAuth default
favourite_team TEXT enum IPL teams Theme accents on onboarding

pools

Column Type Product note
join_code TEXT UNIQUE Permanent invite link identity
created_by UUID Creator cannot be removed
buy_in_amount INTEGER ₹0 = free pool
commission_pct 0–50 Admin-only visibility in UI
distribution_tier winner…top50 Drives Nx prize formula
late_join_policy zero | prorated Fairness without refunds
is_public boolean default false Discovery reserved for V2
max_members default 100 Hard social-scale cap

pool_members

Column Type Product note
role creator | admin | member WhatsApp permission model
status pending…blocked Join lifecycle
payment_status unpaid | paid Separate from approve
is_pinned boolean My Pools sort
UNIQUE(pool_id, user_id) One membership row

matches

Column Type Product note
external_id TEXT UNIQUE CricketData identity
team_a / team_b + names TEXT Abbreviations for UI
scheduled_at / cutoff_at TIMESTAMPTZ Cutoff ~30m before start
status upcoming…no_result Drives predict vs score UI
match_type league…final Future weighted points

match_results

Column Type Product note
winner TEXT Null for abandoned
result_type normal…abandoned Scoring 2/0/1 rules
source api | admin_override Dispute audit trail
UNIQUE(match_id) One result; first-write-wins API thrift

predictions

Column Type Product note
predicted_team TEXT Team A or B code
points_awarded INTEGER nullable Filled after result
UNIQUE(pool_id, user_id, match_id) Multi-pool strategies

leaderboard_cache

Column Type Product note
timeframe weekly | monthly | overall Tabs in Pool Home
period_key TEXT e.g. 2026-W12
total_points, streaks, rank Sync recompute after scores

prizes · pool_budget · achievements

  • prizes: period amounts, winner, paid flag (offline settlement)
  • pool_budget: collected / allocated / paid for admin tracker
  • achievements: hot_streak, perfect_week, team_loyalist, upset_caller (latter deferred)

Critical constraints (product → schema)

Constraint Product rule
UNIQUE (pool_id, user_id, match_id) on predictions Different strategies per pool
join_code unique One permanent link
Results unique per match + ON CONFLICT DO NOTHING One API call per match
payment_status independent of status Approve ≠ Paid
RLS: no self-referential policies (007) Membership checks without recursion
commission 0–50 CHECK Guardrails on admin greed / typos
max_members default 100 Family scale, not stadium scale

Multi-pool isolation

All competitive data keys include pool_id. Never assume global uniqueness of (user_id, match_id) alone. Portfolio skill: multi-tenancy at the grain that matches the social graph.

Membership state machine

pending ──approve──► approved/active ──mark paid──► paid (payment_status)
   │
   └──reject / remove / block

Free pools skip pending (auto-join active).
