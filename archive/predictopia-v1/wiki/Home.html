Predictopia

Multi-group sports prediction leagues that run themselves — schedule, one-tap picks, scoring, leaderboards, and prize tracking. Built for IPL 2026 as a family side project; architected for any sport, any league, any group size.

What is Predictopia?

Running a prediction league by hand is a seasonal tax: Google Sheets, coloured cells, WhatsApp chaos, and manual score tallying across 70+ matches. Predictopia removes that work after pool setup.

The product works in six stages:

  1. Create a pool — name, buy-in (or free), commission, prize distribution
  2. Share one permanent join link — pin it once in WhatsApp
  3. One-tap predictions — Team A or Team B before cutoff
  4. Auto lock & reveal — after deadline, everyone’s picks are visible
  5. Scoring & leaderboards — weekly / monthly / season
  6. Prize tracking — money stays offline (UPI/cash); the app tracks who paid and who won

As a portfolio project, Predictopia demonstrates:

Lived-problem product craft — designed from real family league ops, not abstract market research. Scope is defended by one job: eliminate admin work after setup.

Access-control under pressure — hybrid RLS + API enforcement after a recursive RLS failure and nuclear rewrite (migration 007). A production-shaped lesson in security design, not a tutorial app.

Event-driven prediction rules — cutoff enforced at query time; no toss-detection cron for locks. Clear product rule → simple technical implementation.

Commission-based prize engine — Nx distribution, live preview, rank-inversion guard for ties. Transparent offline money without becoming a payments product (regulatory boundary).

API thrift as product strategy — CricketData schedule via daily cron; results on-demand with first-write-wins cache. Free-tier limits shaped the architecture deliberately.

Screenshot-native growth — every shareable card is an invite (QR + permanent link). Distribution is designed into the UX, not bolted on as “marketing later.”

What makes it technically interesting

RLS nuclear fix (migration 007)

Early pool_members policies queried pool_members to prove membership → infinite recursion. Migration 007 drops all policies on 15 tables and rebuilds with: never self-query the same table in a policy; membership uses auth.uid() = user_id or pools.created_by; fine-grained rules live in API routes where time and role logic are clearer.

Cutoff-enforced prediction engine

Cutoff is ~30 minutes before scheduled start (cutoff_at). Enforcement is now() < cutoff_at in API routes. Before cutoff: only own pick visible. After: pool-wide reveal. Upserts allow change-until-lock; last pick wins.

Commission prize engine

Admin sets buy-in and commission 0–50%. Prize pool = total buy-ins − commission. Distribution tiers (Winner Takes All → Top 50) use Nx shares. Ties split pot shares with a guard so rank inversion cannot pay 2nd more than tied 1st.

CricketData.org integration

  • Schedule: Vercel Cron daily → /api/cron/refresh-schedule upsert
  • Results: first user to open a completed match triggers fetch; ON CONFLICT DO NOTHING → one API call per match

Multi-pool predictions

Predictions are scoped (pool_id, user_id, match_id). One person can run different strategies in different family groups.

Join request + paid states

Paid pools: request → admin approve → admin marks Paid separately (async UPI/cash). Free pools: auto-join.

Native share + QR invites

navigator.share on mobile; clipboard + image fallback on desktop. Cards embed join QR so every screenshot doubles as distribution.
